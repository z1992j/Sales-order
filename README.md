# Sales-order

宽带客资登记与返佣跟踪工具，单人使用。

业务模式是**介绍客资**：把客户信息登记进来，运营商直接对接安装，
完成后按 CPS 结算佣金。所以这个工具关心的不是"收没收到客户的钱"，
而是**运营商什么时候把佣金结给我**。

## 访问

https://z1992j.github.io/Sales-order/

需要访问密码，向管理员索取。

## 功能

### 录入与管理

- 订单录入、编辑、删除、查询；新增时自动提醒重复手机号（含隐藏的非本人归属记录）
- **智能录入**：粘贴一段下单信息自动提取姓名/手机/身份证/地址/套餐等。
  标签后带括号备注、用空格代替冒号都能识别；带宽支持 `1000M` / `1000兆` / `千兆`，
  时限支持「一年」「两年」「18个月」「半年」
- 手动录入时可从地址一键识别省市
- 编辑订单填入**结佣日期**即视为已结佣；未结佣订单在列表里显示已拖欠天数，
  按 30 / 60 天分级着色
- CSV 导入导出、操作日志（含字段级变更明细）

### 筛选

常驻一行，不折叠：**月份 · 省份 · 城市 · 运营商 · 结佣状态**

- 月份下拉按年分组，可选「某年全年」或具体月份
- 城市选项跟随已选省份联动，换省份时自动重置
- 结佣状态用胶囊，一下点中；「逾 30 天 / 逾 60 天」是「未结佣」的子档，
  选中未结佣后才出现
- 顶部「当前口径」一行写明这批数字的范围

### 看板与分析

**全部跟随筛选**——筛到「广东 · 未结佣」，四张卡、趋势图、三张分析卡和表格
统计的都是同一批订单。

| 区域 | 内容 |
|---|---|
| 指标卡 | 本月订单（环比）· 佣金合计 · 未结佣 · 结佣周期（中位数） |
| 趋势图 | 近 12 个月，按已结佣 / 未结佣堆叠；选中某年则显示该年 12 个月 |
| 分析卡（左） | **热销组合**：城市 × 运营商 × 套餐，按笔数排序 |
| 分析卡（中） | **城市 Top 5**：按佣金排序 |
| 分析卡（右） | **运营商表现**：佣金占比 · 单均佣金 · 结佣周期 |

分析卡每一行都可点击，直接套用对应筛选，再点一次取消。

有一条刻意的例外：**按某维度拆分的图不吃自己那一维的筛选**。
趋势图不吃月份筛选、运营商卡不吃运营商筛选、城市卡不吃省市筛选——
否则选中一项后图会被压成一根柱子。这些图改为把选中项高亮。

### 其他

- 响应式布局，手机 / 电脑均可使用；手机端表格保留紧凑列表，点行看详情
- PWA：可添加到主屏，断网时以只读方式展示上次缓存的数据
- 数据若被接口单次返回上限截断，顶部会红色告警——统计算少是会出事的

## ⚠️ 必读：完成数据库配置，登录才真正有用

这个页面是纯静态的，源码任何人都能看到。**只有页面密码是挡不住人的** ——
懂技术的人可以跳过页面，直接拿源码里的 publishable key 去读写数据库。

真正的防线在数据库那一侧，需要你在 Supabase 后台做两件事。**做完之前，
页面顶部会一直显示橙色提醒。**

### 第 1 步：创建登录账号

1. 打开 Supabase 控制台 → 你的项目 → **Authentication** → **Users**
2. 点 **Add user** → **Create new user**
3. 填写：
   - Email：`team@sales-order.local`
   - Password：填页面登录用的那个密码，两边必须一致
   - 勾选 **Auto Confirm User**（不勾的话账号需要邮箱验证，无法登录）
4. 保存

邮箱地址必须和 `app.js` 里的 `AUTH_EMAIL` 完全一致。密码若与页面登录密码
不一致，页面会拿不到数据库令牌，顶部横幅会提示 `Invalid login credentials`。

### 第 2 步：锁死数据库

1. Supabase 控制台 → **SQL Editor** → **New query**
2. 把 [`supabase/security.sql`](supabase/security.sql) 的全部内容粘进去
3. 点 **Run**

这一步会关闭匿名访问，并只放行已登录的请求。脚本可以重复执行，不会动到已有数据。

### 第 3 步：验证

- 刷新页面，重新登录一次，橙色提醒应当消失，数据正常显示。
- 用无痕窗口打开下面这个地址（`KEY` 换成源码里的 publishable key）：
  `https://cgieubqhafwwprwzerty.supabase.co/rest/v1/orders?select=*&apikey=KEY`
  配置成功的话，返回的应该是空数组或 401，而不是订单数据。

如果第 3 步仍然能看到订单，说明 SQL 没执行成功，请回到第 2 步重来。

## 修改密码

密码存在两个地方，必须同时改：

```bash
node tools/hash-password.js 新密码
```

1. 把命令输出的 `PASSWORD_HASH` 那一行替换 `app.js` 中的同名常量。
2. 到 Supabase → Authentication → Users，把 `team@sales-order.local`
   的密码改成同一个新密码。

Supabase 要求密码至少 6 位。建议用长一些的密码：源码里只有哈希值没有明文，
但 6 位纯数字用程序很快就能猜完。

## CSV 导入

按**表头名称**匹配列，所以列的顺序无所谓，多几列少几列也没关系，
只要包含「姓名」和「手机号」两列即可。常见的表头别名都能识别，比如
「客户」等同于「姓名」，「联系方式」等同于「手机号」；旧表头「回款日期」
仍兼容，等同于「结佣日期」。

最省事的做法：先点「导出 CSV」拿到标准模板，在上面改完再导回来。

重复记录按 **手机号 + 办理日期** 判断，导入时自动跳过。

### 几个改代码时容易踩的坑

这些都是踩过之后写进注释的，改相关代码前值得先看一眼：

- **日期一律按本地时区解析**。`new Date('2026-09-01')` 会被当成 UTC，
  东八区显示会差一天。代码里用 `parseYmd()` / `ymd()`，不要用原生解析。
- **给 `<select>` 赋一个选项里没有的值，浏览器会静默置空**。
  智能提取和 CSV 导入可能给出「18个月」这类非预置写法，
  所以有 `setSelectValue()`；同理，设城市前必须先设好省份。
- **拼进 HTML 属性要用 `escAttr()`**，`esc()` 不转义引号。
- **合计行的 colspan 必须跟当前可见列数一致**，手机端靠 CSS 隐藏列，
  写死列数会让表格右侧空出一块。
- **改配色要跑校验**。运营商三色原来在色盲模拟下绿↔黄 ΔE 只有 4.2，
  实际分不开；现在这套是校验过的。
